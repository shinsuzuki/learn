# 詳細設計書 作成プロンプト（テンプレート）

Webアプリケーションの詳細設計書をExcel形式で作成してもらう際に、そのままコピー＆ペーストして使えるプロンプトです。`【　】`で囲んだ部分を対象システムの内容に置き換えてご利用ください。基本設計書がすでにある場合は、その内容（画面一覧・機能一覧・テーブル一覧・API一覧）をもとに詳細化する形で使うと一貫性のある文書になります。

---

## プロンプト本文

```
以下の条件でWebアプリケーションの詳細設計書（サンプル）をExcel形式（.xlsx）で作成してください。
基本設計書（【基本設計書のファイル名 または「なし」】）の内容と整合するように作成してください。

■ 対象システム
- システム名：【例）社内問い合わせ管理システム】
- 対象画面：【例）問い合わせ一覧画面、問い合わせ登録画面、問い合わせ詳細画面】
- 対象処理：【例）問い合わせ登録処理、ステータス更新処理、督促通知バッチ】
- 対象テーブル：【例）問い合わせ、対応履歴、ユーザー、カテゴリ】
- 対象API：【例）問い合わせ登録／一覧取得／詳細取得／ステータス更新／コメント登録／カテゴリ一覧取得／集計レポート取得】

■ 文書として含めてほしい章立て（1章＝1シート、対象数に応じてシートを複製）
1. 表紙（文書番号・版数・作成日・作成者・承認者・関連文書として基本設計書を記載）
2. 改訂履歴
3. 画面詳細設計（画面ごとに1シート）
   - 画面ID・画面名・概要
   - 画面イメージ（レイアウト概要をテキストで表現）
   - 項目定義（No・項目名・種別・データ型／桁数・必須・初期値／備考）
   - イベント仕様（イベントID・発生契機・処理内容・遷移先／備考）
   - 入力チェック仕様（登録・更新系の画面のみ：項目・チェック内容・エラーコード／メッセージ）
4. 処理仕様（主要処理ごとに1シート）
   - 処理ID／処理名・関連API・処理概要
   - 入力パラメータ（項目名・型・必須・説明）
   - 処理フロー（Step・処理内容）
   - 例外処理（ケース・処理内容・HTTPステータス）
   - バッチ処理の場合は起動契機・抽出条件・異常時処理も含める
5. テーブル定義（テーブルごとに1シート）
   - テーブルID・論理名／物理名・概要
   - カラム定義（No・論理名・物理名・データ型・桁数・NOT NULL・PK・FK・初期値・備考）
6. API定義書（全APIの一覧：API-ID・メソッド・エンドポイント・概要・認証・関連処理・詳細シートへのリンク）
7. IF共通仕様（共通リクエストヘッダ・共通HTTPステータスコード・共通エラーレスポンス形式）
8. API I/F定義書（APIごとに1シート）
   - API-ID／名称・エンドポイント・概要
   - パスパラメータ（該当する場合）
   - リクエストパラメータ（項目名・型・必須・説明）
   - レスポンス（HTTPステータスコードと説明）
   - レスポンスパラメータ：配列やオブジェクトを含む場合は「階層」列（1＝トップレベル、2＝配列要素の子項目、3＝さらにその子項目）を設け、子項目は項目名を「├／└」でインデントして親子関係が分かるようにする
   - リクエスト／レスポンスのサンプル（JSON、等幅フォント）
9. エラーコード一覧（エラーコード・区分・メッセージ・発生画面／処理）

■ 体裁・フォーマットの要件
- Excel（.xlsx）、章立てに沿って1シートずつ作成すること
- 2枚目に「シート一覧」シートを追加し、シート名から各シートへジャンプできるハイパーリンクを設定すること
- 各シートに「シート一覧に戻る」リンクを設置すること
- 見出し行はテーマカラーで塗りつぶし、表は罫線・縞模様（ゼブラ）で見やすく整形すること
- JSONサンプルやレイアウトイメージは等幅フォント（Consolas等）を使用すること
- 日本語フォント（游ゴシック等）を使用すること
- 項目はすべて実際の値のサンプルを入れ、プレースホルダーのままにしないこと（架空のシステムとして具体的な画面・処理・テーブル・APIで作成すること）
- 基本設計書がある場合は、画面ID・機能ID・テーブル名などの命名を基本設計書と一致させること

■ 補足
- 内容はサンプルとして作成するため、記載内容は一般的なWebアプリの詳細設計として妥当な粒度・具体性にしてください
- 対象画面・処理・テーブル・APIの数が多い場合は、代表的なもの数件を詳細化し、残りは一覧のみでも構いません
```

---

## 使い方のヒント

- 「対象システム」の5項目（システム名・対象画面・対象処理・対象テーブル・対象API）を書き換えるだけで、別の題材にも流用できます。
- 基本設計書と合わせて使う場合は、先に基本設計書を作成・共有したうえでこのプロンプトを送ると、画面ID（S-01等）や機能ID（F-01等）、テーブル名が自動的に整合します。
- 章立てを増減したい場合は「■ 文書として含めてほしい章立て」を編集してください（例：バッチ設計を独立した章にする、シーケンス図の説明を追加する等）。
